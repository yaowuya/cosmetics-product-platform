### 架构主线

数据主线为「稳定条目 → 可修改草稿 → 不可变发布快照」。编辑提交只改变草稿；发布人核对后，服务端把快照、分类位置、媒体引用、当前指针和审计作为一笔 InnoDB 事务提交。目录请求从当前指针查起，不用草稿填补空字段。

同一企业的 HTTPS 入口提供静态前端，并按路径转交 API。两个客户端都不直连 MySQL 或上传目录。公开读、后台写、图片授权是同一服务内的三个可独立验证的边界。V1 没有跨企业切换、异步发布队列或分端发布逻辑。

### 后端模块设计

按职责划分为公开查询、后台内容维护、发布与历史、媒体、账号审计，以及 schema 迁移入口。公开查询只接收发布版读模型；后台读写从认证依赖取得当前账号。单条和批量共用同一个逐条发布操作，避免校验漂移。仓库现有的是[移动端设计交接包](../../../../docs/cosmetics-platform-design-spec/docs/设计稿细则与需求汇总.md)和[后台稿](../../../../docs/admin-wireframes.html)，没有可沿用的生产 ORM 模型、manager、权限服务或字段长度规范。

#### 字段与存储取舍

正文随单条整体读取与发布，JSON 可保留不同用途的字段，避免按每个显示标签建表；媒体字节留在文件系统，不内嵌正文。高频反查和需要数据库去重的位置使用关联行。历史版本保存图片 ID 而非重复文件；索引字段可从正文提取，但不能形成另一套可单独编辑的产品资料。

#### 逻辑模型与物理存储

每个上述命名实体对应同名 InnoDB 表。目录节点表持有稳定身份，名称和启停由目录配置的发布版本提供。三类产品视图不是三张产品表：后台列表以条目为单位，编辑视图连接草稿，访客视图只连接 `live_id`。会话和操作记录分别持久化，不能从当前权限反推历史操作者。

六个固定位置共用 `content_item`，不加绑定表。后台和公开端按同一个 `config_slot` 定位条目：后台按权限读其草稿，公开端按 `live_id` 读它的发布版。不存在条目或没有发布版时，该处没有已发布配置；不取另一行补齐。目录节点 ID 用于目录树和产品位置，不能代替目录配置条目的身份。

#### 继承字段与重复存储结论

无现存基类或 mixin 需要迁移。SQLAlchemy 的声明式基类只承载映射元数据，不用多表继承区分产品、案例或页面区块。案例对产品的内部引用不是其正文的数据源。

#### 索引、约束与软删除

目录位置和版本号的唯一性由数据库兜底。按历史版本判断是否曾发布，不能只看当前指针是否为空。已发布过的条目保留稳定 ID、版本、引用和日志；归档是退出日常列表，不释放身份。从未发布的草稿才可删除，审计中保留足以识别目标的摘要，不依赖目标行存活。

#### 查询模式与索引映射

| 查询模式 | 过滤/排序/关联字段 | 对应索引或访问路径 | 选择理由 | 证据 |
| --- | --- | --- | --- | --- |
| 定位固定位置配置 | 固定 `config_slot`；条目 ID 或 `live_id` | 用位置唯一索引定位条目，再按主键读草稿或版本 | 后台与访客指向同一条目，不扫描同类配置，也不另建位置索引 | D-022 |
| 公开分类、计数及板块搜索 | 有效节点、版本、线上指针 | 反向索引 `release_place(node_id,release_id)`，再与 `content_item.live_id` 相交 | 排除旧版、停用路径和占位；按产品 ID 去重，分类总数不受细筛影响 | PRD §3.2 |
| 后台全产品、全案例 | 类型、归档、状态、草稿及名称等 | `content_item(kind,archived_at,id)` 限定候选，草稿按主键查；分类用 EXISTS | 每款一行；首版范围内做子串匹配，不假定普通索引能加速前置通配符 | PRD §3.3、§3.4 |
| 历史、关联案例及公开素材 | 条目 ID、关联产品 ID、素材 ID | 版本按条目与序号倒序；仅在案例集合查其草稿和线上关联；`release_asset(asset_id,release_id)` 再核实当前公开引用 | 下架提示按案例去重；仅历史引用不能取公开图 | D-013、PRD §3.3 |
| 幂等核对、账号和条目审计 | 请求号、目标、时间、操作者 | 唯一请求键；`(target_kind,target_id,occurred_at)`、`(actor_id,occurred_at)` | 区分提交成功但丢回执与实际未提交；依对象或人员追溯 | D-015、PRD §4.3 |

#### 生命周期数据归属

条目的线上指针决定公开版本；草稿存在与否单独判断。版本是只读证据，恢复会复制成新的草稿修订，不会移动线上指针。归档、撤权以及用户主动取消的效果分别由条目、账号和未触发写入表达，不共用含义模糊的状态字段。

#### Migration 影响

本次是新建 schema。固定位置字段与约束纳入首版 Alembic 迁移，无生产历史数据迁移或回填。七条未归类示例和假二维码不得作为默认公开种子。后续升级先核对 Alembic 版本、做一致性备份、在恢复副本演练，再显式执行迁移并发布应用。MySQL 的 DDL 不等于可整批事务回滚；没有安全逆迁移时恢复已验证的对应应用与备份，不在线反复试错。

#### 技术栈专项结论

只用 SQLAlchemy 2 的映射、工作单元与 InnoDB 约束；Alembic 脚本审查实际 DDL 和数据影响。无须为说明文字变动生成空迁移。单条发布是数据库事务单位，文件上传先完成，不能假设数据库能回滚文件写入。

### 状态、并发与执行流程

1. **保存**：登录且可编辑，按条目 ID 和期望修订号比较并写入。首次或部分保存可缺业务资料；结构不合法仍拒绝。修订不符返回冲突，不做最后写入者覆盖。批量追加分类按每款的当前草稿取并集；没有草稿时从当前资料开始，只对实际变更生成草稿。
2. **检查**：校验真实素材、必填项和可展示位置，输出条目、修订、缺项、影响位置。检查不生成版本。批量仅发布人可见逐款结果，禁用或无权后不再返回该结果。
3. **确认**：按条开启事务，核对当前账号状态和发布权；与授权变更使用一致的行锁顺序。取得目标条目锁后以当前读核对请求号：同一操作已成功则返回原版本，键被用于不同内容则冲突。新请求校验草稿修订、仍有效的目录和媒体依赖，并与目录变更串行化关键检查。再写快照、位置、图片引用、线上指针和审计，消费这份草稿并提交。失败全部回滚。不同请求号也不能把同一次修订发布两次。
4. **批量**：客户端只对已确认的合格款发起各自的确认请求；不跨款开启大事务。不假定关页能取消已到达服务端的请求。网络结果未知时先核对原请求号或条目记录，不把超时算作失败或成功。
5. **下架、清理、恢复**：下架只清当前条目的线上指针。产品下架或归档前返回关联案例供确认，列表有变化时重新提示；不修改案例。删除仅限从未发布草稿，归档仅限已下架且有历史的条目，均在提交时重查条件。恢复明确的版本，覆盖已有草稿前核对条目修订并确认；写新草稿和恢复日志，不改线上内容。

### 接口、权限与兼容边界

约定 `/api/public` 只读，`/api/admin` 依赖当前会话。下表为路由族；请求标识是服务器分配的稳定 ID。列表返回条目、总数和分页位置，顺序相同时以 ID 稳定排序。管理员身份不默认放行内容接口。

| 入口与方法 | 输入 → 结果 | 访问条件与失败处理 |
| --- | --- | --- |
| `GET /api/public/pages/{page}`、`/catalog`、`/products[/{id}]`、`/cases[/{id}]`（后几条同 public 前缀） | 页面或板块、分类、筛选、关键词 → 当前发布投影 | 不登录；搜索与计数先限制当前有效范围，不公开草稿、历史、关联产品或账号；详情未发布统一 404 |
| `GET /api/public/media/{id}` | 媒体 ID → 字节流 | 每次对当前公开内容检查引用，撤下最后引用后返回 404；不能绕过检查直连上传目录，不能让共享缓存长时间代为放行 |
| `POST /api/admin/login`、`logout`、`change-password`；`GET /api/admin/me` | 凭据 → 安全 Cookie；读取当前能力标志 | HTTPS、HttpOnly、Secure、SameSite；写请求校验来源和防跨站请求令牌。强制改密前只允许改密、退出。限速登录，不记录明文口令 |
| `GET/POST /api/admin/products`、`cases`；`GET /api/admin/items/{id}`；`PUT .../draft` | 筛选、创建、正文及期望修订 → 稳定 ID、线上信息和草稿修订 | 编辑权；删除草稿 `DELETE .../draft` 仅在满足首次草稿条件且二次确认时执行；分类追加仅 products |
| `POST /api/admin/media` | 限量上传 → 媒体 ID；登记上传者 | 当前有编辑权；检查实际图片格式、大小、像素及解码结果，禁止可执行内容与路径穿越。上传本身不产生公开引用。 |
| `GET /api/admin/media/{id}` | 媒体 ID 及所处内容 → 字节流 | 当前有编辑权，且媒体确由指定条目的当期草稿或历史版本引用。未关联上传仅上传者本人可读。图片地址不授予权限，禁共享缓存。 |
| `GET /api/admin/items/{id}/preview?revision=…` | 条目 ID 和有效修订号 → 指定草稿和授权图地址 | 当前有编辑权。服务端独立校验参数与条目；修订已变化返回 409，不退回线上版或最新版。预览禁共享缓存。 |
| `POST /api/admin/items/{id}/{check,publish,unlist,archive}`；`POST /api/admin/products/batch-check` | 检查 → 逐项原因；确认携带期望修订和独立请求键 → 版本或冲突 | 发布权；请求目标和当前授权须重新核实。批量检查不产生任何写入，不接受对案例的批量发布 |
| `GET /api/admin/items/{id}/versions` | 条目 ID → 该条目的版本记录；展开时按条目与版本定位 | 当前有编辑权；不返回其他条目的版本。历史图片走私有读取。 |
| `POST /api/admin/items/{id}/versions/{seq}/restore`；页面及目录配置使用同一草稿/上线操作 | 恢复请求带来源版本及期望条目修订 → 新草稿修订 | 恢复要求有效编辑权，不要求发布权；无编辑权返回 403。替换已有草稿须经确认，修订不符返回 409，不改草稿。成功只写新草稿和含操作者、来源版本的恢复日志，不改线上指针；发布另验发布权。 |
| `GET/POST /api/admin/accounts`、`PATCH .../accounts/{id}`；`GET /api/admin/audit` | 开通、停用、授权或收回；依账号或条目查询关键动作 | 账号管理限管理员，审计按所属治理或内容权限裁剪；撤权后旧页面不享有缓存权限 |

401 表示会话不存在或失效；403 表示当前账号无权；409 表示修订、目标状态或请求号冲突。对后台私有读，有编辑权但资源不存在或不在允许范围内时返回 404。发布校验不合格时返回可定位的字段和原因（单条确认 422，批量检查正常返回逐款结论）。业务错误不伪装为成功，错误体不得带出内部路径或密码。V2 小程序只消费公开发布投影，V1 不提供另一套发布接口。

### 风险、迁移、发布、回滚与监控

| 具体失败场景 | 影响 | 预防或处理 | 发布/回滚/监控安排 | 证据 |

| 单机失效或磁盘占满 | 两端不可用、上传中断 | 数据库及文件在容器外持久化；先落完不可变文件再登记资产，失败不提供该文件 | 限制对外端口，监测容量、上传错误、服务健康、事务失败和备份年龄；无双机高可用承诺 | D-005、D-006 |
| 数据库和媒体备份时间点错开 | 还原后仅有图 ID 无图 | 在一致窗口内冻结写入，完成数据库备份及其引用文件清单和文件拷贝，再开放写入；保存版本标识与校验信息 | 加密保存到异机，在隔离环境按同一恢复点恢复卷、目录与兼容镜像，核对媒体后再开放流量 | D-019 |

| 数据库与应用版本不匹配 | 升级期间写错 schema | 先备份演练，迁移在显式升级窗口执行；数据库只用内部网络 | schema 兼容时回退应用，否则隔离写入后协调数据恢复及恢复点后的业务核对 | D-018 |

| 首版做法与理由 | 适用上限 | 可验证的重访条件 | 升级方向 |
| --- | --- | --- | --- |

实现时在事务、授权、媒体可见性和版本幂等边界附近说明不变量。提交前自审新增公开接口的契约说明及关键注释，逐项对照实际授权、事务与失败语义，不用通过的行为测试替代说明核对。
