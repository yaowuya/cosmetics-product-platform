## 执行与边界

- 产品源码基线：`feat/cosmetics-showcase-mvp` / `f7a30fe`。Windows、Node 24.22.1、Python 3.12.15、本机已有 MySQL 8.0.42、Chrome 157.0.8103.79。浏览器主用例记录时间为 UTC 2026-11-22 15:50–16:01。本次只增加测试、测试输入和验收记录，未改应用或部署代码。
- 后端：在非默认端口、身份和 datadir 都已核对的专用 MySQL 上执行完整 `backend/tests`，**20 passed、2 failed**。`test_docker_runtime_prerequisite` 缺 Docker；`test_clean_host` 缺获准的异机恢复清单。均是全套件真实失败，不纳入上面的业务用例计数，不把它们改为通过。
- 前端：工作区两端 typecheck 与生产 build 通过，**22 项 Node 测试通过**；真实 Chrome 控件尺寸、选中态、键盘测试通过。38 条浏览器**执行记录**含 setup、补充项、重测，不能当成 38 项独立通过。真实轮播复测间隔 4019 ms；服务图与弹层、修订冲突、旧历史恢复 409 和旧预览 409 均有独立记录。
- 浏览器全部业务写入通过 UI 发起；无接口拦截、响应替换、业务数据注入或数据库 seed。样例站 `5143` 只读，本轮写入使用 `5155` 的一次性企业和新数据库，`5144` 项目实例仅核对健康。没有写入 `3306` 项目库或 `auto-ops`，没有下载 MySQL 或连接云服务器。
- 回执丢失后按原键核单有单元和事务测试，但本轮没有制造“已提交未收到回执而下一款尚未发起”的真实网络中断；切换预览目标时的真实迟到响应反序也未作全链路证明。正式视觉独立评审、跨主机恢复和物理设备均不由本报告替代。
- 五分钟巡检覆盖任务终态、异常退出和隔离服务就绪；断言失败后保留结果并诊断，没有把失败的写入批次重复派发。用例跑完后已结束巡检并关闭专用站点；原有样例站和项目站健康检查均为 200。
