# 本机 MySQL 实机验收 · 2026-11-22

**结论：指定项目库已迁移，PC、H5 和 API 已实际联通。下列浏览器主流程跑通；本记录不是全量视觉通过、正式上线、异机恢复或 `fp-final-review`。**

## 环境与执行

- 项目实例：`https://localhost:5144`，仅回环监听。MySQL 8.0.42，`localhost:3306/cosmetics-product-platform`。操作前只读确认库存在、零表；显式运行 Alembic 到 `0002_config_items`，`alembic check` 无差异。运行账号仅具该库的 DML 权限，未用数据库管理员身份运行 HTTP 服务。没下载新 MySQL；没有访问 `auto-ops`。
- 桌面和匿名手机视口分别为 1440×900、390×844，DPR 1，zh-CN、light；Chrome 157。旧的隔离本地数据演示在 5143，用于有内容的产品、案例、海报与联系弹层对稿，不是第二家企业独立上线。样例素材无一内置于正式前端。
- 浏览器通过已安装 Playwright 打开真实构建并操作页面。`Mocked Core API: false`。除了正式首管 bootstrap，账号、草稿、图片、发布、恢复、下架、归档、停用都由 UI 发起；不依靠拦截、DB seed 或直接 API 写。单元/集成套件不充当浏览器证据。
- 浏览器执行：`node .local/showcase/verify.cjs <已安装的 Playwright> setup|revise|restore|clean`（四个独立阶段，脚本与身份状态仅在受限本机目录）。从 15:09 至 15:18 UTC；脱敏请求见工作区 `.local/showcase/acceptance.ndjson`，不含 body、令牌或密码。仅可读匿名页面的按钮检查：`node frontend/tests/h5-controls.e2e.mjs https://localhost:5143`。本地资料不是通用数据库导入工具，勿对企业库重放批量验收。

## 观察结果

| 验证 | 可复核的结果 |
| --- | --- |
| 登录与角色 | 首管先改密，从账号管理页面分别开通 E（仅编辑）、P（编辑和发布）。独立浏览器会话；匿名打开四个 H5 入口均读取真实公开 API。 |
| 产品草稿 | E 新建不完整产品 7，P 用名称、未上线和有草稿筛出一条。批量检查列出缺项并禁用「发布这 0 款」。E 取消删除不改变列表，再确认删除返回 204，刷新后消失。 |
| 发布与草稿隔离 | E 上传图 1，创建案例 8。私有修订预览可读，匿名案例和图返回 404。P 显式确认 v1，匿名详情读到第一版且图片实际解码。修改后，私有窗为第二版、线上窗仍为第一版；核对差异表后 P 发布 v2。 |
| 修订与恢复 | 从真实编辑页另存后重开旧预览只返回 409，非法参数不发预览请求。E 持旧页恢复返回 409；刷新后取消覆盖不发写入，再同意才产生恢复审计，新稿内容等于 v1，匿名仍读 v2。A 撤 P 发布权后，P 的旧确认页 POST 得 403；恢复权限后另行检查、发布 v3。 |
| 退出线上与回收 | P 取消下架时匿名内容不变；确认后案例详情及失去最后公开引用的图片返回 404。P 按原名找回下架案例并归档，日常列表清空，归档列表仍可读取三版历史，私有历史图片可解码。两个 QA 账号均已停用，旧编辑页写入 401。最后只读查库：0 个 live、0 个草稿、案例 8 已归档，3 次发布、1 次恢复、1 次下架、1 次归档。保留审计，不物理删除历史。 |
| 对稿验证 | 独立内容实例经真实 UI 建立的四张海报、目录、三款产品和案例，可从公开 H5 搜索、清空、打开两种详情、返回、开闭联系弹层。对照两份用户指定 HTML，实测并修复 uni-app 的原生按钮 CSS；390 px 下分类行 48 px、轮播点点击区 21×26 px、案例筛选高 29 px，键盘 Enter 可选中。有图案例须等图片解码再截，不能把等待态当成终态。 |

首次 setup 发现自动化选择器按整段 label 文本查找失败，核实浏览器可访问树后改按 combobox 角色；无需放宽页面校验。clean 第一次因真实登录限流 429 停止，未关闭限速；第二次复现下架后列表丢名称；修复后从实际的下架状态继续，一次归档成功，未重放已提交写入。HTTPS 探针直连回环、验证本地证书，不依赖 OS HTTP 代理。

## 不可替代的门禁

- 后端完整套件：20 passed、2 failed。两个失败是 `test_docker_runtime_prerequisite`（无 Docker）和 `test_clean_host`（无获批第二企业与异机恢复清单）；只跑本机集合为 20 passed、2 deselected。数据库回归只在非 3306、专用账户、匹配专用数据目录的临时库执行。
- 真实物理手机、实际企业二维码、第二独立部署、干净异机恢复、批量真实丢回执与全部 14 工作流未获完整实测。两份静态稿没有画齐所有错误态；这些功能冒烟不使任何缺少审批图/独立视觉核验的 case 成为 `VISUAL_REVIEW_PASS` 或 `FRONTEND_E2E_PASS`。目前不进入正式终审和归档。
