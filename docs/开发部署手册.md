# 开发部署手册

仓库根目录执行命令。秘密、口令和证书不写入本文件或 Git。线上编排是 `docker-compose.yaml`，启动时自动读取同目录的 `.env`。

## 名字

| 项 | 值 |
| --- | --- |
| 项目、容器、数据库 | `cosmetics-product-platform` |
| 数据库账号 | `showcase`，只允许容器网段连接 |
| 公开 H5 | `https://<主机>:5000/` |
| 管理后台 | `https://<主机>:5001/admin/` |
| 代码 | 线上只从 Git 拉取，不把源码拷进服务器 |

数据库名带连字符。SQL 里写成 `` `cosmetics-product-platform` ``。连接串路径可以直接写这个名字。

## 本地开发

需要 Python 3.12+、MySQL 8 和 Node 24（或 Node 22.18+）。打开仓库根目录，解释器用 `.venv`。

本机秘密放在 `.local/showcase/`，不要写进代码或共享配置：

| 文件或变量 | 用途 |
| --- | --- |
| `database.url` 或 `DATABASE_URL` | `mysql+pymysql` 连接串，库名用 `cosmetics-product-platform` |
| `media/` 或 `ASSET_ROOT` | 素材目录 |
| `tls.crt`、`tls.key` | 覆盖 `localhost` 的证书，本机入口才用 |

```sh
python -m pip install -e ".[test]"
make db-upgrade
make serve
```

`make serve` 只监听 `https://127.0.0.1:5144/`。它不启动 MySQL，不迁移，也不创建账号。

前端：

```sh
make web-install
make web-admin
make web-h5
make web-build
```

管理端开发地址是 `http://127.0.0.1:5173/admin/`，H5 是 `http://127.0.0.1:5174/`。这两个地址只看页面。登录和正式预览用上面的 HTTPS 入口。

空库创建首个管理员。口令交互输入，至少 6 个字符，最多 128 个。管理员身份本身没有编辑或发布权。

```sh
make bootstrap LOGIN=admin
make seed-weitai
```

`seed-weitai` 只补目录、案例分类和联系文案。已经发布过的配置会跳过。

## 线上手动启动

在服务器的仓库目录执行，当前是 `/data/cosmetics-product-platform`。先拉代码，再启动。不要用拷贝覆盖仓库。

```sh
git pull --ff-only
chmod -R a+rX .
chmod 600 .env
docker compose up -d
```

网段、端口、路径和初始账号都写在仓库根目录的 `.env`，不要写进 `docker-compose.yaml`。第一次把 `.env.example` 复制成 `.env` 再填写。`.env` 不提交。`chmod -R a+rX .` 之后必须把 `.env` 收回 `600`，否则口令会被容器用户读到。

线上目录都用项目名，不再使用 `/data/showcase`：

| 目录 | 用途 |
| --- | --- |
| `/data/cosmetics-product-platform` | 代码 |
| `/data/cosmetics-product-platform-assets` | 素材，属主 UID 10001 |
| `/data/cosmetics-product-platform-secrets` | 连接串、证书和初始口令，权限 `700` |

`SHOWCASE_DATABASE_URL_FILE` 指向密钥目录里的主机 MySQL 连接串，库名是 `cosmetics-product-platform`。API 容器不发布端口。`.env` 里的 `SHOWCASE_HTTPS_PORT` 只出 H5，`SHOWCASE_ADMIN_HTTPS_PORT` 只出管理端，两边都反代同源 `/api`。浏览器要接受这台机器的证书。

容器用户是 UID 10001，仓库目录必须对它可读。克隆时如果目录是 `700`，上面的 `chmod` 不能省。容器直接读取拉下来的代码。改了 Python 或页面后，拉代码并重启即可：

```sh
git pull --ff-only
chmod -R a+rX .
chmod 600 .env
docker compose up -d
```

前端有改动时，拉代码后先构建，再启动：

```sh
npm ci --prefix frontend
npm --prefix frontend run build
docker compose up -d
```

只有 `pyproject.toml` 里的 Python 依赖变了，才重建镜像：

```sh
docker compose build api
docker compose up -d
```

## 已发布产品的目录缩略图

更新服务器代码后，在仓库目录重启 API 并运行回填：

```sh
docker compose restart api
docker compose run --rm --no-deps api python -m app.cli.backfill_thumbnails
```

命令为当前目录可见的已发布产品生成 320 × 320 WebP 缩略图，保留原图、素材 ID 和发布记录。优先使用单独上传的目录方图，缺少方图时以产品封面等比例缩放并补白。已生成的缩略图会跳过，命令可重复运行。发布产品时采用相同规则。从产品封面生成的缩略图缺失时，列表显示占位图，详情页使用原封面。

缩略图存放在素材目录的 `.thumbnails` 子目录，可以从原图重新生成。原图备份中不包含该目录，恢复后可重新运行上述命令。

## 新机器第一次

主机 MySQL 里先建空库，并让 `showcase` 账号只能从容器网段访问：

```sql
CREATE DATABASE `cosmetics-product-platform` CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

准备好秘密文件和证书后，复制 `.env.example` 为 `.env` 并填好初始口令：

```sh
git clone --branch feat/cosmetics-showcase-mvp --depth 1 https://github.com/yaowuya/cosmetics-product-platform.git /data/cosmetics-product-platform
cd /data/cosmetics-product-platform
cp .env.example .env
docker compose build api
npm ci --prefix frontend
npm --prefix frontend run build
docker compose run --rm api alembic -c alembic.ini upgrade head
docker compose run --rm api python -m app.cli.bootstrap
docker compose run --rm api python -m app.cli.seed_weitai
docker compose up -d
```

`/health/ready` 只表示数据库和当前迁移可用，不显示连接串。备份和恢复仍用 `deploy/backup.sh`、`deploy/restore.sh`，说明在 `deploy/runbook.md`。
